# Codex 트레이스 리더 · 제품 요구사항 (PRD)

**사용자가 위임한 작업을 직접 관찰하고, 결과를 판단하는 데 필요한 실행 근거를 찾을 수 있어야 한다.** 첫 구현은 Windows의 로컬 Codex 채팅 한 건에서 시작한다. 사용자는 작업 개요에서 개별 행동과 원본으로 이동하며, 화면에서 확인 가능한 범위와 빠진 근거를 함께 확인한다. [에이전트 위임의 철학](product-philosophy.md) · [실행과 사용법](../README.md)

## 1. 제품 범위

대상은 코딩 에이전트에 작업을 위임하거나 에이전트의 문제 해결 과정을 살펴보는 사람이다. 사용자는 완료 보고의 근거를 조사할 수도 있고, 별도의 질문 없이 성공한 작업이나 낯선 도구 사용을 둘러볼 수도 있다.

| 구분 | 요구사항 |
| --- | --- |
| **기록 단위** | 같은 채팅의 rollout과 상세 번들을 여러 개 등록할 수 있다. 대화 보기는 선택한 rollout과 검증한 이전 구간을 읽는다. 상세 보기는 선택한 번들 하나를 읽는다. |
| **기본 탐색** | 작업 개요 → 요청·구간 → 행동·관계 → 원본과 그 사이의 복귀를 제공한다. 상세 번들이 없는 채팅도 세션 기록으로 탐색할 수 있다. |
| **표기 언어** | 화면과 고정된 행동 유형명은 한국어를 사용한다. 기록된 자연어 메시지와 코드·원문은 보존한다. |
| **후속 범위** | 실시간 감시·런타임 개입, 번들 간 이벤트 병합, 다중 채팅 분석, 자동 진단·프롬프트 추천, 선택형 로컬 번역은 별도 요구사항으로 다룬다. |

탐색 기능의 수용은 근거 조회와 복귀를 재현할 수 있는지로 판단한다. 정신모형의 변화와 위임 판단의 전이는 사용성 평가에서 별도 가설로 다룬다.

## 2. 사용자 흐름

사용자는 최근 채팅이나 세션 파일을 열면 작업 개요에서 바로 탐색을 시작한다. 개요와 네 보기는 하나의 행동 ID를 공유하며, 검색과 원본 조회를 오가는 동안 선택 맥락을 보존한다.

| 조작 | 기대 동작 |
| --- | --- |
| **채팅 열기** | 로컬 최근 채팅을 최신순으로 최대 100개 표시한다. 제목, 첫 요청, 날짜로 찾거나 `rollout-*.jsonl` 파일을 직접 선택한다. |
| **기록 소스 선택** | 등록한 rollout 또는 상세 번들을 고른다. 선택한 소스, 기록 상태, 확인된 범위와 제한을 개요에서 볼 수 있다. 같은 채팅의 추가 rollout과 상세 번들을 찾거나 직접 등록할 수 있다. |
| **요청·작업 구간 탐색** | 개요에서 요청과 작업 구간을 훑는다. 기록된 진행 메시지와 규칙으로 분류한 구간을 구별한다. 관심 있는 구간을 이야기로 읽거나 첫 행동의 원본으로 바로 이동한다. |
| **행동 보기 전환** | 이야기·흐름도·타임라인·원본 보기에서 관심 행동을 따라간다. 접힌 반복 호출이나 하위 실행은 구성 행동 수를 표시하고 원래 행동을 펼칠 수 있게 한다. |
| **검색과 상세 읽기** | 기록 검색에서 행동으로 이동한다. 오른쪽 상세의 **넓게 읽기**에서 긴 본문을 문장 경계에 맞춰 읽고, 목록·목차·본문 검색을 이용한다. 서식과 원문을 전환하고 상세로 돌아갈 수 있다. |
| **근거 확인과 복귀** | 원시 JSONL이 있으면 위치와 본문을 표시한다. 원본을 보고 이전 보기의 행동과 읽던 위치로 돌아간다. 같은 채팅·턴 ID가 확인된 경우 대화와 상세 트레이스 사이를 이동하며, 여러 번들이 대응하면 선택지를 표시한다. |
| **갱신** | 등록한 활성 rollout과 연결된 이전 구간, 선택한 번들을 다시 읽는다. 동일한 사건이 남아 있으면 선택과 위치를 복원한다. 실패 시 확보한 이전 스냅샷과 이전 확인 시점을 유지한다. |

최근 채팅은 처음 열거나 목록을 갱신할 때 로컬 `sessions`를 확인한다. 추가 rollout은 사용자가 찾기를 요청할 때 탐색하며 Codex 표준 위치의 날짜 폴더와 `archived_sessions`를 확인한다. 상세 트레이스는 채팅을 열거나 사용자가 다시 찾을 때 확인한다. 경로를 옮기거나 삭제한 경우 영향받는 경로와 원인을 표시하고 다시 지정할 수 있게 한다.

## 3. 데이터 계약과 근거 수준

**소스의 소속, 기록 범위, 보기에서 만든 표시를 각각 검증한다.** 같은 채팅이라는 확인은 소속을 보장한다. 채팅 전체가 해당 번들에 기록됐는지는 번들의 실제 범위로 판단한다.

| 소스 | 읽기와 연결 규칙 |
| --- | --- |
| **`rollout-*.jsonl`** | 채팅 ID와 물리 rollout ID를 구별한다. `history_base`를 복원할 때 이전 파일의 ID와 지정 바이트·순번 경계를 검사한다. 복원이 불가능하면 누락 범위를 알리고 읽은 구간을 표시한다. 원본 줄의 위치는 실제 물리 파일을 가리킨다. |
| **`manifest.json`** | `root_thread_id`로 채팅 소속을 확인하고 `trace_id`로 중복을 제거한다. 번들은 `started_at_unix_ms` 최신순으로 표시하며, 같은 시각에는 ID로 순서를 고정한다. |
| **`state.json`** | 공식 reducer의 파생 상태를 사용해 스레드·턴·모델 요청·도구 및 관계를 표시한다. 대화와 상세는 같은 루트 채팅의 `turn_id` 및 `codex_turn_id`가 대응할 때 연결한다. |
| **`trace.jsonl`, `payloads/`** | 확보한 원시 줄은 위치와 본문을 표시한다. 페이로드 누락·잘림·참조 전용은 확인된 파일이나 ID와 함께 표시한다. 압축 샤드 본문 전체를 복원하는 별도 디코더는 후속 범위다. |

세션에서 복원된 이전 기록, 되돌리기 전후의 rollout, 여러 번들을 구별하는 기준은 물리 소스 ID와 검증된 기록 경계다. 각 소스의 상태와 상세 스키마 구조는 Codex 기록 형식을 따른다. [Codex 기록 계보 복원 코드](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/thread-store/src/local/rollout_lineage.rs#L65-L188) · [Codex Rollout Trace](https://github.com/openai/codex/blob/main/codex-rs/rollout-trace/README.md)

| 표시하는 주장 | 필요한 근거와 범위 |
| --- | --- |
| **기록된 값** | 원시 레코드 또는 파생 상태에 해당 필드가 있다. `completed`는 호출 종료를, 종료 코드 `1`은 명령의 결과값을 나타내므로 각각 표시한다. |
| **확인된 연결** | 명시적인 호출·반환·요청·주체 ID를 사용한다. 도구의 `model_visible_output_item_ids`와 모델 요청의 `request_item_ids`가 일치하는 항목을 해당 요청에 포함됐다고 표시한다. 같은 이름의 호출은 ID로 구별한다. |
| **규칙 기반 표현** | 도구 이름과 대상은 기록된 도구 종류와 인자에서 구성한다. 시각, 순번, 동일 시각의 ID에 따른 정렬은 표시 순서를 정한다. 구간·반복 묶음에서 구성 이벤트와 원래 행동으로 접근할 수 있다. |
| **부분 기록·미확인** | `history_base` 불일치, 기록이 닫히지 않았거나 마지막 줄이 불완전한 경우, 원시 본문이 없거나 잘린 경우, 실제 관계를 확인할 ID가 없는 경우를 표시한다. |
| **해석의 범위** | 모델 입력에 포함된 사실, 응답에서 인용한 사실, 산출물에 반영한 사실은 각각 별도 근거가 필요하다. 원인, 방법론 적용 여부, 작업의 전체 성공은 관측값만으로 분류하지 않는다. |

## 4. 구현 경계

**Desktop 앱은 로컬의 등록된 기록을 읽기 전용으로 처리한다.** 상세 변환은 검증한 실행 파일과 임시 복사본을 사용하며, Renderer에는 기록 읽기에 필요한 동작만 노출한다.

1. **Main.** 세션·번들 경로와 채팅 식별자를 확인하고, 파서와 reducer를 실행한다. 상세 번들은 `CODEX_ROLLOUT_TRACE_ROOT`, Windows 로컬 `codex-rollout-traces`, 사용자가 지정한 검색 위치에서 찾는다. 현재 상세 지원 형식은 데스크톱 스키마 3이다.
2. **Reducer.** 기록에 사용한 Codex 실행 파일을 확인한 뒤 `codex debug trace-reduce <임시 번들> --output <임시 상태 파일>`을 인수 배열로 호출한다. 지원 형식·경계·결과 식별자를 검증하고 실패 이유를 표시한다. 파싱에 성공한 결과는 소스별로 한 단위로 반영하며 오래된 갱신 결과가 최신 선택을 덮어쓰지 않게 한다.
3. **Preload와 Renderer.** 읽기·등록·갱신·근거 조회에 필요한 IPC만 제공한다. 로그의 명령, HTML, URL, 파일 경로는 표시 데이터로 취급한다. 원본 기록에 대한 쓰기, 외부 전송, 임의 실행과 등록 범위 밖 읽기는 허용하지 않는다.
4. **공통 실행 그래프.** Main의 스냅샷에 사건·주체·정보 항목과 유형별 관계를 구성한다. 사건 ID는 기존 행동 ID를 사용한다. 위치와 접근 가능 여부는 `EvidenceRef`에, 소스별 기록 경계는 `SourceCoverage`에 보존한다. Renderer의 네 보기에는 현재 `Timeline` 계약을 사용한다. 그래프 기반 탐색 상태, 기존 보기의 그래프 연동, 에피소드 모델은 후속 범위다. [실행 그래프 계약](../src/shared/execution-graph.ts) · [이슈 #3](https://github.com/LeeMinH123/codex-trace-reader/issues/3)

## 5. 수용 기준

| 시나리오 | 확인할 결과 |
| --- | --- |
| **채팅 열기와 소속 검증** | 상세 번들 없이도 세션을 열 수 있다. 같은 채팅의 미등록 번들만 후보로 표시한다. 불일치·미확인 번들의 연결을 보류하고 `trace_id` 중복을 막는다. |
| **이전 구간과 되돌리기** | 올바른 바이트·순번 경계까지 복원한다. 되돌린 구간은 해당 원본 rollout에서 찾을 수 있고, 확인된 턴 ID를 통해 대화와 상세를 오간다. |
| **동일 행동과 복귀** | 검색, 네 보기, 원본을 오갈 때 동일 행동을 찾는다. 개요 또는 이전 보기에서 출발한 위치를 복원한다. 반복·중첩 묶음의 구성 행동에 접근한다. |
| **기존 근거로 직접 확인** | 완료 보고나 추가 검토 문서 없이 작업 구간에서 관심 행동의 기록 위치와 원본 근거까지 이동할 수 있다. 확보한 근거의 범위를 화면에서 확인할 수 있다. |
| **긴 본문 탐색** | 제목이 있는 문서에서 목차로 이동하고, 본문·목록 검색과 이전·다음 일치 이동이 동작한다. 원문 전환에서 줄바꿈과 들여쓰기를 볼 수 있다. 좁은 창에서도 읽기 화면에 들어가고 `Esc`로 출발 버튼에 복귀할 수 있다. |
| **출처와 의미** | 동명 호출이나 같은 시각의 사건을 구별한다. 재파싱에서 동일 사건의 ID와 순서를 유지한다. 종료 코드와 호출 종료가 구별되고, 모델 입력 포함은 기록 ID가 증명하는 경우에 표시된다. |
| **부분 기록과 복구** | 누락·잘림·참조를 구분한다. 갱신·변환 실패 또는 경로 유실 시 해당 소스와 실패 이유, 이전 결과가 있다면 이전 확인 시점을 표시한다. |
| **권한 경계** | 로그에 있는 명령·HTML·URL·외부 경로 때문에 실행, 외부 탐색, 등록 범위 밖 파일 읽기, 네트워크 전송이 발생하지 않는다. 원본은 읽기 전용으로 처리한다. |

회귀 확인은 `npm test`, `npm run typecheck`, `npm run build`, `npm run build:portfolio`로 수행한다. 긴 문서, 성공한 실행, 여러 rollout, 부분 기록, 종료·반환이 불일치하는 경우를 검증 사례에 포함한다.

## 6. 사용성 평가와 가설 검증

**탐색 성과, 근거 판단, 학습 전이를 별도로 평가한다.** 클릭 수나 체류 시간만으로 이해 또는 위임 개선을 판정하지 않는다.

| 평가 대상 | 관찰과 판정 기준 |
| --- | --- |
| **탐색 성과** | 근거를 찾는 데 걸린 시간과 동선을 기록한다. 실행 주체, 입력·결과, 관계를 정확히 읽고 뒷받침되는 결론의 범위를 설명하는지 확인한다. |
| **자발적 탐색** | 힌트 전에 무엇을 펼쳐 보는지, 어떤 질문을 만들고 어떤 기록으로 이어가는지 관찰한다. |
| **이해의 형성** | 사용자가 본 내용을 자신의 말로 설명하게 한다. 확인 사실과 가설을 구별하고, 이전 가정이 달라졌다면 그 근거를 짚을 수 있는지 본다. |
| **학습 전이** | 해설에 앞서 도구나 문맥이 다른 새 사례를 제공한다. 근거의 한계와 위임·확인·개입의 선택을 어떤 원리에 따라 판단하는지 확인한다. 장기 전이는 실제 후속 작업으로 따로 평가한다. |

탐색적 평가에서는 경험 수준이 다른 사용자 3~5명부터 시작한다. 같은 범위의 평면 로그와 리더를 비슷한 난도의 사례에 적용하고, 사례와 형식의 순서를 교차 배정한다. 먼저 성공 사례를 자유롭게 둘러보고 이어서 지정 과제를 수행하게 한다. 전이는 두 번째 형식이나 해설을 접하기 전에 별도 사례로 확인한다. 기록 활성화, 실행 파일 선택, reducer 변환에 드는 준비 비용도 따로 기록한다.
